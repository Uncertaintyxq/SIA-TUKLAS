## 2. Rules enforced on the server (not just hidden in the UI)

1. **Private until approved.** Any work not `approved` is returned only to its author, its assigned adviser, or an admin. Every other request gets 404, the same as a missing work, so its existence doesn't leak. Feed, portfolio and search queries filter in SQL.
2. **Who decides.** Only the assigned adviser or an admin can approve, request revision, or reject. Allowed transitions: `submitted → revision | approved | rejected`, `revision → approved | rejected`. `approved` and `rejected` are final. Only the author can resubmit (`revision → submitted`).
3. **Ads are academic only.** `category` must be one of `colloquium | innovation | cpgarcia`, checked by Zod and by a MySQL `ENUM`. Only educators and admins can post. A non-admin's ad is always saved as `pending`, whatever the request says. Only `approved` ads are listed.
4. **Honors start Pending.** A new honor from a non-admin is saved with `verified = false`, whatever the request says. Only an admin can verify or decline. The public sees only verified honors; the owner and admins see "Pending verification".
5. **Roles from the token.** JWT in an httpOnly cookie. Role checks use the user loaded from the DB, never a role sent by the client.

Client libraries: React Router, TanStack Query, Framer Motion, Lucide, dnd-kit (accessible drag-and-drop with keyboard support).
Server libraries: Express, Prisma, Zod, jsonwebtoken, bcrypt, cookie-parser, helmet, express-rate-limit (on login).
Dev setup: Vite proxies `/api` to `localhost:4000`, so client and API share one origin and there's no CORS or cookie trouble.

## 4. Data model (Prisma → MySQL)

- `User` id, name, email (unique), passwordHash, role `student|educator|admin`, program, headline, timestamps
- `Work` id, author → User, adviser → User, type `research|literary`, title, abstract (TEXT), tags (JSON), status `submitted|revision|approved|rejected`, approvedAt, approvedBy → User, timestamps
- `Comment` id, work → Work, author → User, text, createdAt
- `Opportunity` id, adviser → User, kind `mentorship|grant|call`, title, description, deadline, slots?, createdAt
- `Event` id, postedBy → User, category `colloquium|innovation|cpgarcia`, title, description, venue, date, status `pending|approved|rejected`, createdAt
- `Background` id, user → User, degree, school, year
- `Honor` id, user → User, kind `award|grant|certification`, title, issuer, year, verified, verifiedBy?, verifiedAt?

Seed: the 6 prototype people (Andrea, Paolo, Kim, Dr. Santos, Prof. Aquino, Lea) and all their works, comments, opportunities, events, background and honors. Dates are computed relative to the seed time ("12 days ago"), like the prototype.

## 6. Design system

- **Tokens** in `tokens.css`: purple `#6C4AB6`, gold `#FFCB57`, blue `#53C0E8`, lavender `#ECE6FF`, off-white `#F8F9FD`, ink `#222221`, plus Inter.
- **Contrast (WCAG AA):** gold and blue fail as text on white, so they're used only as fills behind ink text. Text versions use the darker shades from the prototype (`gold-700 #8A6200`, `blue-700 #1F6F8E`). Every text/background pair is checked in phase 6.
- **Looks:** `data-appearance="modern|classic"` × `data-theme="light|dark"`, so 4 combinations. Classic follows the prototype's 2000s-LinkedIn styling: Verdana, gradients, square corners, gradient card headers.
- **44px targets:** every button, chip, tab and nav item has at least 44px of hit area, Classic included. Classic keeps its compact *look* (smaller font, gradients), but its controls are taller than in the prototype (26px there).
- **Responsive:** sidebar becomes a drawer under 860px, 2-column layouts stack under 1080px, no horizontal scroll at 320px.
- **Tuko:** an SVG gecko in a gold grad cap, as a React component with poses `idle` (empty states) and `cheer` (success moments: submission sent, work approved).
- **Motion (Framer Motion):** page transitions, featured-research slider (feed header), events carousel, sliding tab underline (`layoutId`) on feed chips / admin tabs, a 3-step Submit form that slides between steps (Details → Abstract & keywords → Review & submit), animated modals and toasts, loading skeletons. `MotionConfig reducedMotion="user"` plus CSS `prefers-reduced-motion` turns the movement into instant changes or fades.

## 8. Decisions made (tell me if you want any changed)

- **"Continue as" buttons** stay as one-click demo logins. They log in as the seeded Andrea / Dr. Santos / Lea, and only appear when `VITE_DEMO_LOGIN=true` (on by default in dev).
- **Reset demo data** works only when `DEMO_MODE=true` on the server.
- **"Educator" vs "Research adviser":** the design notes leave this open. I use **Educator** as the role name and "Research adviser" where the prototype does (the adviser picker, the review copy).
- **Appearance and theme preferences** are saved in the browser (localStorage), not in the DB.
- **Tags** are a JSON column on `Work`, not a separate table. Search uses `LIKE` across title, abstract, tags and author name, which is fine at this scale.

## 9. Visual direction: the Research Notebook (chosen Oct 22)

Each work is an entry in a witnessed research notebook. Adviser approval is the notebook's "Witnessed & understood by" line, with a gold seal.
- **Look:** graph-paper margins with a blue margin rule, lavender index tabs for navigation, a purple bookcloth login cover, and frosted vellum (blur) for the header, menus, modals and toasts.
- **Fonts:** Archivo for headings, Martian Mono for entry numbers, dates and seal codes, Inter for body text.
- **Spacing:** every spacing value is a multiple of the 8px grid cell.
- **Color:** purple only on things you can act on, and one 9-step lavender→ink ramp for all neutrals.
- **Motion:** pages slide in and come into focus, tabs slide, the witness signature draws in, the seal stamps down, and Tuko reacts.
- **Where it's recorded:** `client/PRODUCT.md` (product brief) and `client/.impeccable/surfaces/src-app-tsx.md` (direction contract). DESIGN.md is written from the finished build at the end of phase 6, after a design finish review.
